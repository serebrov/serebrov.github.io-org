* Git Server
:PROPERTIES:
:CUSTOM_ID: git-server
:END:
Prerequisites are git and ssh-server (=apt-get install openssh-server=).

The installation process is described in [[https://git-scm.com/book/en/v2/Git-on-the-Server-Setting-Up-the-Server][the Pro Git book]].

Below is the setup process with some comments and updates.

Add the git user and set a password (you will be asked for it):

#+begin_src shell
  $ sudo adduser git
#+end_src

Log in as the git user and set up authorized ssh keys:

#+begin_src shell
  $ su git
  git@localname$ cd ~
  git@localname$ mkdir .ssh
#+end_src

For each user who needs access to the server, add the user's public key to
=~/.ssh/authorized_keys=. To generate a new key pair for the user, use
=ssh-keygen= (see [[https://docs.github.com/en/authentication/connecting-to-github-with-ssh/generating-a-new-ssh-key-and-adding-it-to-the-ssh-agent][GitHub manual]] for details).

#+begin_src shell
  git@localname$ cat /home/usera/.ssh/id_rsa.pub >> ~/.ssh/authorized_keys
  git@localname$ cat /home/userb/.ssh/id_rsa.pub >> ~/.ssh/authorized_keys
#+end_src

Change permissions for the =.ssh= folder and the =authorized_keys= file:

#+begin_src shell
  git@localname$ chmod 600 ~/.ssh/authorized_keys
  git@localname$ chmod 755 ~/.ssh
#+end_src

Make a dir for repositories and init bare repositories:

#+begin_src shell
  git@localname$ mkdir ~/server
  git@localname$ cd server
  git@localname$ mkdir project.git
  git@localname$ cd project.git
  git@localname$ git --bare init
#+end_src

Security - set git-shell for the git user:

#+begin_src shell
  # check where git-shell is
  $ which git-shell
  /usr/bin/git-shell

  # edit /etc/passwd
  $ sudo vim /etc/passwd

  # find the string for the git user:
  git:x:1000:1000::/home/git:/bin/sh
  # change the shell for the git user:
  git:x:1000:1000::/home/git:/usr/bin/git-shell
#+end_src

On the user side - clone the repository or add a remote to an existing repository:

#+begin_src shell
  # clone
  $ git clone ssh://git@server.host.name/home/git/server/project.git

  # or add a remote
  $ cd project
  $ git remote add origin ssh://git@server.host.name/home/git/server/project.git
#+end_src

For =server.host.name=, there are several options:
 * if the server has a domain name, just use it
 * use the server IP address instead of the host name
 * use any host name you like and add it to the local hosts file to map to the IP address

** Possible problems and solutions
:PROPERTIES:
:CUSTOM_ID: possible-problems-and-solutions
:END:
*** git-shell shows the "Interactive git shell is not enabled." message
:PROPERTIES:
:CUSTOM_ID: git-shell-shows-the-interactive-git-shell-is-not-enabled.
:END:
This is OK and it will work. Additional setup can be done to allow the
git user to log in via ssh and execute special commands like =list= to
get a repository listing. See:
 * =man git-shell=
 * =cat /usr/share/doc/git/contrib/git-shell-commands/README=
 * https://serverfault.com/questions/285324/git-shell-not-enabled

*** When the user tries to execute a server operation, git asks for the git user password instead of the ssh key passphrase.
:PROPERTIES:
:CUSTOM_ID: when-the-user-tries-to-execute-a-server-operation-git-asks-for-git-user-password-instead-of-ssh-key-passphrase.
:END:
Check the auth log (=/var/log/auth.log=) for errors. In my case there were
errors related to git user's =.ssh= and =authorized_keys= permissions:

#+begin_example
  Aug 15 15:25:24 seb-ubu sshd[4561]: Authentication refused: bad ownership or modes for file /home/git/.ssh/authorized_keys
  ...
  Aug 15 15:47:48 seb-ubu sshd[7145]: Authentication refused: bad ownership or modes for directory /home/git/.ssh
#+end_example

Changing access permissions as described above fixed the issue.

*** How to make an existing git repository bare
:PROPERTIES:
:CUSTOM_ID: how-to-make-existing-git-repository-bare
:END:
If you already have a repository and want to put it on the server, then
it seems to be safe to just copy the =.git= folder from the existing
repository:

#+begin_src shell
  # source: project/.git
  $ cp -r project/.git project.git
  $ cd project.git
  $ git config --bool core.bare true
#+end_src

* Git Server - email notifications on push
:PROPERTIES:
:CUSTOM_ID: git-server---email-notifications-on-push
:END:

Git already has a script to handle email notifications after a push. Check
=/usr/share/doc/git/contrib/hooks/post-receive-email= for instructions:

#+begin_src shell
  $ sudo chmod a+x /usr/share/git-core/contrib/hooks/post-receive-email
  $ cd /path/to/your/repository.git
  $ ln -sf /usr/share/git-core/contrib/hooks/post-receive-email hooks/post-receive
#+end_src

Configure notifications:

#+begin_src shell
  $ cd /path/to/your/repository.git

  # who should receive notifications
  $ git config hooks.mailinglist "user1@example.com user2@example.com"

  # send emails from
  $ git config hooks.envelopesender git@myserver.com

  # email subject prefix
  $ git config hooks.emailprefix "[Git]"

  # project name - edit the 'description' file in the git repository folder
  $ vim description
#+end_src

The post-receive-email script requires sendmail to work. Below is a
description of the sendmail setup process.

* Set up sendmail on Ubuntu
:PROPERTIES:
:CUSTOM_ID: setup-sendmail-on-ubuntu
:END:
Install it:

#+begin_src shell
  $ sudo apt-get install sendmail
#+end_src

Check your hosts file - in my case sendmail was incredibly slow, and this
was fixed by the following line in =/etc/hosts=:

#+begin_src shell
  127.0.0.1 localhost.localdomain localhost myhostname <--- order matters!!!
#+end_src

Note that you need to use the same order as above -
localhost.localdomain, localhost and then myhostname (replace myhostname
with your real host name, check the output of the =hostname= command).

Send a test email:

#+begin_src shell
  $ echo "My test email being sent from sendmail" | /usr/sbin/sendmail myemail@domain.com
#+end_src

If you have problems with emails, check the log: =/var/log/mail.log=
and the error log: =/var/log/mail.err=.

** Set up SMTP for sendmail
:PROPERTIES:
:CUSTOM_ID: setup-smtp-for-sendmail
:END:
If you want to set up an SMTP server for your emails, do the following:

#+begin_src shell
  $ cd /etc/mail
  $ sudo mkdir auth
  $ sudo chmod 700 auth
  $ sudo vim client-info
#+end_src

Enter the following line into the client-info file:

#+begin_src shell
  AuthInfo:smtp.server.com "U:mymail@server.com" "I:mymail@server.com" "P:mypassword"
#+end_src

Here you put your SMTP server name (instead of =smtp.server.com=) and
your credentials. =U= is an SMTP user (usually your email), =I= is an
account (usually also your email), and =P= is a password. See details for
parameters [[https://web.archive.org/web/20130606091121/http://www.scalix.com/wiki/index.php?title=Configuring_Sendmail_with_smarthost_Ubuntu_Gutsy][here]].

Continue setup:

#+begin_src shell
  $ sudo bash -c "makemap hash client-info < client-info"
#+end_src

Edit the =/etc/mail/sendmail.mc= and add the following lines before the
=MAILER_DEFINITIONS= line:

#+begin_src shell
  define('SMART_HOST','smtp.server.com')dnl
  define('confAUTH_MECHANISMS', 'EXTERNAL GSSAPI DIGEST-MD5 CRAM-MD5 LOGIN PLAIN')dnl
  FEATURE('authinfo','hash /etc/mail/auth/client-info')dnl
#+end_src

Process the sendmail.mc with m4:

#+begin_src shell
  $ sudo bash -c "m4 sendmail.mc > sendmail.cf"
#+end_src

Restart sendmail:

#+begin_src shell
  $ sudo service sendmail restart
#+end_src
