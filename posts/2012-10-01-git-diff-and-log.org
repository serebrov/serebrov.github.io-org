#+TITLE: git: viewing changes using diff and log
#+DATE: <2012-10-01>
#+TYPE: note
#+FILETAGS: :git:
#+DESCRIPTION: Tips on using git diff and git log.

* Diff and log between two branches (to see all changes on both branches)
:PROPERTIES:
:CUSTOM_ID: diff-and-log-between-two-branches-all-changes-on-both-branches
:END:
To see all changes between two branches, use =diff= with two or three
dots and =log= with three dots between branch names.

Note: the confusing part is that =log= with two dots only shows changes
on one branch, while =diff= with two dots includes changes on both
branches (showing changes from one branch as removed and from another
branch - as added). See the section below on how to see only new changes
on the branch.

For example, we have a history like this:

#+begin_example
    ... A ---- B ---- C ---- D  master
               \
                E ---- F  branch
#+end_example

** List of new commits on both branches (log with three dots):
:PROPERTIES:
:CUSTOM_ID: list-of-new-commits-on-both-branches-log-with-three-dots
:END:

#+begin_src shell
git log master...branch

commit F
commit D
commit E
commit C

# With --left-right it shows additional markers for commits
git log --left-right master...branch
commit > F
commit < D
commit > E
commit < C
#+end_src

** Diff with two dots, =master= commits shown as removed changes, =branch= commits - as added:
:PROPERTIES:
:CUSTOM_ID: diff-with-two-dots-master-commits-shown-as-removed-changes-branch-commits---as-added
:END:
#+begin_src shell
git diff master..branch
-changes from C,D
+changes from E,F

# Same without dots
git diff master branch
-changes from C,D
+changes from E,F
#+end_src

** Diff with two dots, =branch= commits are shown as removed changes, =master= commits as added:
:PROPERTIES:
:CUSTOM_ID: diff-with-two-dots-branch-commits-are-shown-as-removed-changes-master-commits-as-added
:END:
#+begin_src shell
git diff branch..master
+changes from C,D
-changes from E,F

# Same without dots
git diff branch master
+changes from C,D
-changes from E,F
#+end_src

* Diff and log between two branches (only branch changes)
:PROPERTIES:
:CUSTOM_ID: diff-and-log-between-two-branches-only-branch-changes
:END:
Often, we want to only see changes on the branch, without seeing what
has changed on master (or on another base branch).

In this case, we can use =git log= with two dots to get the list of
changes and =git log -p= to see the diff (while =git diff= with two dots
will still show changes from the base branch, so is not suitable for
this task).

For example, we have a history like this:

#+begin_example
    ... A ---- B ---- C ---- D  master
               \
                E ---- F  branch
#+end_example

** List of new commits on =branch= (log with two dots):
:PROPERTIES:
:CUSTOM_ID: list-of-new-commits-on-branch-log-with-two-dots
:END:
#+begin_src shell
git log master..branch
F
E
#+end_src

** List of new commits on =branch= (cherry):
:PROPERTIES:
:CUSTOM_ID: list-of-new-commits-on-branch-cherry
:END:
#+begin_src shell
git cherry master
+ F
+ E

git cherry -v master
+ F commit message
+ E commit message
#+end_src

The =git cherry= command provides a more compact output with the list of
new commits on the =branch= compared to =master=.

** List of new commits on =master= (log with two dots):
:PROPERTIES:
:CUSTOM_ID: list-of-new-commits-on-master-log-with-two-dots
:END:
#+begin_src shell
git log branch..master
D
C
#+end_src

** Diff, only new commits on =branch= (log with two dots and =-p= or diff with three dots):
:PROPERTIES:
:CUSTOM_ID: diff-only-new-commits-on-branch-log-with-two-dots-and--p-or-diff-with-three-dots
:END:
#+begin_src shell
git log -p master..branch
+changes from F
+changes from E

git diff master...branch
+changes from E
+changes from F
#+end_src

** Diff, only new commits on =master= (log with two dots and =-p= or diff with three dots):
:PROPERTIES:
:CUSTOM_ID: diff-only-new-commits-on-master-log-with-two-dots-and--p-or-diff-with-three-dots
:END:
#+begin_src shell
git log -p branch..master
+changes from D
+changes from C

git diff branch...master
+changes from C
+changes from D
#+end_src

* Git diff and log inconsistency
:PROPERTIES:
:CUSTOM_ID: git-diff-and-log-inconsistency
:END:
In the sections above we can see that git diff and git log with three
and two dots seem to behave inconsistently:

- =git log master..branch= - only new commits on =branch=
- =git diff master..branch= - changes on both =master= and =branch=
- =git log master...branch= - new commits on both =master= and =branch=
- =git diff master...branch= - only changes on =branch=

The [[https://git-scm.com/book/en/v2/Git-Tools-Revision-Selection#_commit_ranges][definition]] of two and three dots:

- Double Dot - range of commits that are reachable from one commit but
  aren't reachable from another (in other words, new commits on branch
  that are not present on master)
- Triple Dot - all the commits that are reachable by either of two
  references but not by both of them (changes on both branches, but not
  common changes before that).

And =git log= does exactly that - new commits on the branch with two
dots and all new commits on both branches with three dots.

While =git diff= works differently, here is a summary from the man page:

#+begin_example
Comparing branches

        $ git diff topic master    (1)
        $ git diff topic..master   (2)
        $ git diff topic...master  (3)

    1. Changes between the tips of the topic and the master branches.
    2. Same as above.
    3. Changes that occurred on the master branch since when the topic branch was started off it.
#+end_example

This is why I like =git log -p= to show diffs instead of =git diff=. It
is more consistent and easier to remember - fewer dots (two) - fewer
changes (only new changes on the branch), more dots (three) - more
changes (changes on both branches):

- =git log master..branch= - only new commits on =branch=
- =git log -p master..branch= - only changes on =branch=
- =git log master...branch= - new commits on both =master= and =branch=
- =git log -p master...branch= - changes on both =master= and =branch=

* Diff staged changes
:PROPERTIES:
:CUSTOM_ID: diff-staged-changes
:END:
Show staged changes - added to index, but not committed yet:

#+begin_src shell
git diff --cached
# or
git diff --staged
#+end_src

* Diff pulled changes
:PROPERTIES:
:CUSTOM_ID: diff-pulled-changes
:END:
Show diff of changes pulled from upstream:

#+begin_src shell
git pull origin
git diff @{1}..
#+end_src

Here =@= means =HEAD= and =@{1}= means “prior value of the HEAD”, the
list of prior values can be seen with =git reflog=.

* Log without merge commits
:PROPERTIES:
:CUSTOM_ID: log-without-merge-commits
:END:
To show the log without merge commits use =--no-merges= flag:

#+begin_src shell
git log --no-merges
#+end_src

* Log without another branch commits
:PROPERTIES:
:CUSTOM_ID: log-without-another-branch-commits
:END:
To exclude commits on =master= (or another) branch, use =--not= flag:

#+begin_src shell
git log contrib --not master # or git log contrib ^master
#+end_src

To exclude both commits on =master= and merge commits:

#+begin_src shell
git log contrib ^master --no-merges
#+end_src

What was added in remote branch, but not in local:

#+begin_src shell
git log origin/featureA ^featureA
#+end_src

Note: these three commands are equivalent:

#+begin_src shell
git log refA..refB
git log ^refA refB
git log refB --not refA
#+end_src

Show all commits that are reachable from =refA= or =refB= but not from
the =refC=:

#+begin_src shell
git log refA refB ^refC
git log refA refB --not refC
#+end_src

* Git log formatting
:PROPERTIES:
:CUSTOM_ID: git-log-formatting
:END:
Log with diff (p), only last two entries:

#+begin_src shell
git log -p -2
#+end_src

One line log:

#+begin_src shell
git log --pretty=oneline
#+end_src

Log with graph:

#+begin_src sh
git log --pretty=format:"%h %s" --graph
#+end_src

Format log:

#+begin_src sh
git log --pretty=format:"%h - %an, %ar : %s"
#+end_src

Log formatting options:

#+begin_example
%H  Commit hash
%h  Abbreviated commit hash
%T  Tree hash
%t  Abbreviated tree hash
%P  Parent hashes
%p  Abbreviated parent hashes
%an Author name
%ae Author e-mail
%ad Author date (format respects the --date= option)
%ar Author date, relative
%cn Committer name
%ce Committer email
%cd Committer date
%cr Committer date, relative
%s  Subject
#+end_example
