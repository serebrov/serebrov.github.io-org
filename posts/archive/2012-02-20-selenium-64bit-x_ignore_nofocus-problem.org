#+TITLE: Selenium: problem with loading =x_ignore_nofocus.so=
#+DATE: <2012-02-20>
#+TYPE: note
#+FILETAGS: :web:
#+DESCRIPTION: How to fix Selenium failing to start Firefox on 64-bit Linux, when it loads the 32-bit libX11 library.

Problem: selenium fails to start Firefox with the following error:

#+begin_quote
The browser appears to have exited before we could connect.
The output was: Failed to dlopen /usr/lib/libX11.so.6\ndlerror
says: /usr/lib/libX11.so.6: wrong ELF class: ELFCLASS32\n
#+end_quote

In my case it was reproduced on the 64-bit machine with [[http://aws.amazon.com/amazon-linux-ami/][Amazon Linux AMI]]. The
problem itself is known and there is [[http://code.google.com/p/selenium/issues/detail?id=2852][an issue in selenium tracker]].

It is because =x_ignore_nofocus= library tries to load 32-bit version of
the =libX11= instead of 64-bit. In my system there are the following versions of =libX11=:

#+begin_src shell
find / | grep libX11.so.6
#+end_src

#+begin_example
/usr/lib64/libX11.so.6       <-- symbolic link to `libX11.so.6.3.0'
/usr/lib64/libX11.so.6.3.0 <-- ELF 64-bit LSB shared object, x86-64, version 1 (SYSV), dynamically linked, stripped
/usr/lib/libX11.so.6          <-- symbolic link to `libX11.so.6.3.0'
/usr/lib/libX11.so.6.3.0    <-- ELF 32-bit LSB shared object, Intel 80386, version 1 (SYSV), dynamically linked, stripped
#+end_example

On the right side (after "<--") is an output of =file /usr/libX/libX11.so.6xxx=.

* Solution

Change symbolic link =/usr/lib/libX11.so.6= to point to the 64-bit
version =/usr/lib64/libX11.so.6.3.0=:

#+begin_src shell
mv /usr/lib/libX11.so.6 /usr/lib/libX11.so.6.bak
ln -s /usr/lib64/libX11.so.6.3.0 /usr/lib/libX11.so.6
#+end_src

After that selenium started to work.
