#+TITLE: Angular.js and SEO, pre-render content on the server
#+DATE: <2013-05-24>
#+TYPE: note
#+FILETAGS: :js:
#+DESCRIPTION: How to improve SEO for the Angular.js app.

With angular.js you have an HTML which looks like this:

#+begin_src html
  <span>{{variableValue}}</span>
  <ul>
      <li ng-repeat="item in items" ng-bind="item.name"></li>
  </ul>
#+end_src

The way to make this content SEO-friendly is to pre-render the data
on the server and then let angular do its job on the client.

For simple variables there is [[http://docs.angularjs.org/api/ng.directive:ngBind][ng-bind]]. And for lists there is [[http://docs.angularjs.org/api/ng.directive:ngInclude][ng-include]].

Here is the example from above with pre-rendered content:

#+begin_src html
  <span ng-bind="variableValue">Static indexed value</span>
  <ul ng-include="'your/dynamic/list'">
      <li>seo-friendly item1</li>
      <li>seo-friendly item2</li>
  </ul>
  <script type="text/ng-template" id="your/dynamic/list">
      <li ng-repeat="item in items" ng-bind="item.name"></li>
  </script>
#+end_src

This way we have initial content for search bots and instructions for
angular at the same time.

Note that the solution above works for simple cases but it may not work
well for complex pages or if there are many pages. Actually what we do
is duplicate the content - we provide static content on the server side
and then angular requests content dynamically and overrides the static data.

A better (and more complex) solution is to crawl the website and save
static page snapshots for search engines.

This can be done with a headless browser like [[http://phantomjs.org/][PhantomJS]] which you can
run periodically to generate static page snapshots.

There is also an easy way to do this with a service like [[http://www.brombone.com/][BromBone]].

It will do the complex part of the job for you and you only need to
redirect search bots to static versions of your pages generated by BromBone.
