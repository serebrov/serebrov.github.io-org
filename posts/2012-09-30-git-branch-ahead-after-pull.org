#+TITLE: git: your branch is ahead of 'origin/master' by 1 commit after pull
#+DATE: <2012-09-30>
#+TYPE: note
#+FILETAGS: :git:
#+DESCRIPTION: What to do when git reports that your branch is ahead of master.

Git reports that:

#+begin_quote
Your branch is ahead of 'origin/master' by 1 commit (or X commits)
#+end_quote

after you do the =git pull origin master=.

The sequence of actions:

- There is a change in the =origin/master=
- We do the =git pull origin master=
- The change is received and merged
- =git status= shows "Your branch is ahead of 'origin/master' by 1 commit."

The reason is that after the =pull origin master= the reference to the
remote =origin/master= is not changed (still points to the older version)
and only your local copy of the branch is updated.

The problem is that =git pull origin master= is the wrong command (unless you intentionally
wanted to only update the local branch).

Solution: use =git pull= instead.
It will fetch remote changes, update remote references and merge remote changes to your local branch.
Or use =git fetch=. It will fetch remote references, but will not merge to your
local branch, and you do it manually by running =git merge origin/master=.

To check the state, run:

#+begin_src shell
git diff origin/master
#+end_src

It will show the difference and it should be the last master change.

To fix the problem, run:

#+begin_src shell
git fetch origin
#+end_src

This will update git links to remotes.

If you have this problem then you likely wanted to just do =git pull= instead of =git pull origin master=.
