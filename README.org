#+TITLE: Blog

A static blog made from org files with the Emacs HTML exporter (=ox-html=).
A small JavaScript file adds the reader features in the browser.

* Layout
| Path         | Content                                                     |
|--------------+-------------------------------------------------------------|
| =posts/=     | One org file per post. Images and videos go in =posts/images/=. |
| =posts/archive/= | Old posts. They are not on the index page.              |
| =posts/files/= | Downloadable files (scripts, configuration files) that posts link to. |
| =layout/=    | =header.html= and =footer.html=: the site header (logo, name, menu) and footer of every page. The build marks the menu link of the current section (=data-section= "posts", "archive", or "tags") with =aria-current=. |
| =static/=    | =blog.css= and =blog.js=, copied to every build.            |
| =publish.el= | The export settings, the =video:= link type, and the build command. |
| =blog-tags.el= | The tag cloud, the tag pages, and the tag links on posts. |
| =public/=    | The build output. You can put it on any static host.        |

* URLs
The site must be at the root of its domain (for example https://serebrov.github.io/), because pages link to =/static/=.

| Source                         | URL                            |
|--------------------------------+--------------------------------|
| =posts/<name>.org=             | =/html/<name>.html=            |
| =posts/archive/<name>.org=     | =/html/<name>.html=            |
| =posts/images/<file>=          | =/html/images/<file>=          |
| =posts/files/<file>=           | =/html/files/<file>=           |
| =index.org= (made by the build) | =/= (=index.html=)            |
| =archive.org= (made by the build) | =/archive.html=             |
| =tags/index.org= (made by the build) | =/tags/= (tag cloud)     |
| =tags/<tag>/index.org= (made by the build) | =/tags/<tag>/=     |

The =/html/<name>.html= URLs are the same as on the old Hugo site. Thus the file name of a post sets its URL. Do not rename a published post. Posts and archive posts go to the same directory, so their file names must be different.

In a post, link to another post with a relative path, for example =./2015-05-20-cloudwatch-setup.html=. Link to a file as =files/<file>=.

* Requirements
- Emacs with Org 9.8 or later.
- The =htmlize= package from MELPA. The build finds it in the package directory of your Emacs (=~/.emacs.d/elpa/=).

* Commands
| Command        | Result                                           |
|----------------+--------------------------------------------------|
| =make build=   | Export the posts that changed to =public/=.      |
| =make rebuild= | Export all posts again.                          |
| =make serve=   | Build, then serve =public/= on http://localhost:8000. |
| =make clean=   | Remove =public/= and the export cache.           |

In Emacs, load =publish.el= and run =M-x blog-publish=. With =C-u=, it exports all posts again.

=make build= exports only the org files that changed. After you change =layout/= or =publish.el=, run =make rebuild= to update all pages.

To convert multiple files from markdown to org:

#+begin_src shell
for mdf in $(ls *.md); do pandoc -f markdown -t org -o ${mdf%.*}.org $mdf; done;
#+end_src

* Write a post
1. Add =posts/YYYY-MM-DD-slug.org= with =#+TITLE=, =#+DATE=, =#+DESCRIPTION=, and =#+FILETAGS=.
2. Run =make serve= and open the post from the index page.

The index page (=index.html=) lists the posts in =posts/=, newest first, by =#+DATE=.

* Page features
- Folding :: Click a heading to fold its section. Add the tag =:folded:= to a heading to close it when the page opens.
- Section links :: Each heading gets an id from its title, for example =#code-blocks=. Set =CUSTOM_ID= to use a different id.
- Code :: htmlize colors the code at build time with the Emacs major mode of the language. The colors for each face (=.org-keyword=, =.org-string=, and more) are in =static/blog.css=. Each block has a copy button.
- Code results :: The build does not run code. For a block with =:exports both=, the =#+RESULTS:= that are in the file go to the page.
- Images :: A link to an image file, for example =[[file:images/diagram.svg]]=, shows the image. Add =#+CAPTION:= above it for a caption. =M-x yank-media= pastes an image from the clipboard to =posts/images/= and inserts this link (see =posts/.dir-locals.el=).
- Video :: =[[video:images/clip.mp4]]= or =[[video:https://example.com/clip.mp4]]= shows a video player.
- Tags :: Write the tags of a post as =#+FILETAGS: :git:aws:=, with colons. The export does not split tags at spaces, so =#+FILETAGS: git aws= is one tag "git aws". The end of each post links to its tag pages. The =/tags/= page shows all tags; the font size grows with the number of posts. Each tag page lists the posts and archive posts with this tag, newest first. The build makes all tag pages again on each run. The sidebar of each page (below the content on narrow screens) shows the tag cloud too. Thus a change of tags changes every page: after you add a post or change tags, run =make rebuild= (=make build= updates only the changed posts).
